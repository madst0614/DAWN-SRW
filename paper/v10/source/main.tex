\begin{abstract}
Dense Transformers place computation inside large dense transformations, leaving the identity of the state transformations executed for a particular input implicit. We introduce DAWN-SRW, which formulates language-model computation as state-conditioned addressing in learned operation spaces populated by explicit read-write (RW) state-transition operators. A residual state is mapped to operation queries; each operator has an address derived from its own read and write directions; and selected rank-1 operators are composed to construct attention queries, keys, values, and a post-attention residual-state transition. At 393.8M parameters and 39.999B training tokens, DAWN-SRW retains language-model performance relative to a parameter- and token-matched dense Transformer: the C4 cross-entropies are 2.9402 and 2.9359, and six-task zero-shot means are 0.4629 and 0.4597, respectively. A descriptive 1.272B-parameter evaluation reaches 2.8359 C4 cross-entropy and a 0.4858 zero-shot mean. Mechanistically, a discovery-frozen 4,096-site Q/K-centered RW operator circuit passes suppression, four matched-control families, and exact restoration on independent validation and fully held-out indirect-object-identification inputs. The model also exhibits exact input-conditioned functional support, but the current dense implementation evaluates full operator pools and is not hardware-efficient. These results establish explicit addressed RW operators as a viable and causally analyzable computational substrate for language modeling, without claiming benchmark superiority or current sparse-execution efficiency.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Transformers preserve and refine information in a residual stream, but the
computational units that change that state are usually implicit inside dense
matrices. Multi-head attention and feed-forward layers expose useful module
boundaries, yet they do not report which individually identifiable state
transformations were chosen for a token. This makes it difficult to separate
the question \emph{what is represented now?} from \emph{which transformation
should execute now?}

Prior work provides an important read-write view of dense feed-forward
computation: a feed-forward layer can be analyzed as a collection of keys that
detect input patterns and values that contribute outputs
\cite{geva2021transformer}. That view identifies functionally meaningful
directions in an existing dense layer. It does not, by itself, make each unit a
globally addressable operator object whose selection is exposed and whose
execution can be reused across depth.

We ask:
\begin{quote}
\emph{Can language-model computation be organized by addressing explicit
read-write state-transition operators in learned operation spaces?}
\end{quote}
\DAWN{} answers this question with two architectural choices. First, a
\emph{learned operation space} contains addresses for executable
transformations rather than representations of the current token state.
Second, each computational unit is an explicit rank-1 \emph{RW operator}: it
reads a scalar from the residual state and writes that scalar along a learned
direction. State-conditioned addressing maps the current residual state to an
operation query, compares that query with operator addresses derived from the
operators' own read and write functions, and composes the admitted operators.

The same mechanism constructs the query, key, and value states used by causal
self-attention and the residual-state transition after attention. Q and K make
separate selections from one shared QK pool; V and the post-attention residual
transition (RST) use separate pools. The pools and addressing projections are
reused across depth, while normalization and attention output projections
remain layer-specific. Thus, represented state and executable operation
identity are separated without claiming that the evaluated model executes
read-write operations in a low-dimensional residual space.

The empirical study follows a fixed evidence order. We first compare a 393.8M
parameter \DAWN{} checkpoint with a parameter- and token-matched dense
Transformer on C4 and six zero-shot tasks. We then report descriptive 1.272B
results, measure exact input-conditioned operator support, and localize a
discovery-only indirect object identification (IOI) circuit. The circuit is
frozen before confirmatory data are opened, then tested with suppression,
matched controls, and exact restoration on independent validation and fully
held-out test inputs. Finally, we report three fail-closed boundaries: RAVEL
localization, ARC causal validation, and 1.3B IOI localization. Efficiency is
not a headline result: the current implementation scores and applies full
operator pools densely.

Our contributions are:
\begin{enumerate}
    \item \textbf{Learned operation spaces.} Language-model states address
    executable transformations in learned coordinate spaces rather than
    invoking only fixed layer-local dense maps.
    \item \textbf{Explicit RW operators.} Each unit is an explicit rank-1
    read-write state transition, and its address is derived from its functional
    read and write parameters.
    \item \textbf{Attention-wide and cross-depth reuse.} Reusable,
    route-specific pools construct Q, K, V, and post-attention residual
    transitions; Q and K share a pool while retaining separate selections.
    \item \textbf{Empirical and causal evidence.} We report matched 400M
    performance retention, descriptive 1.3B evaluation, exact functional
    support, and a discovery-frozen IOI circuit confirmed by validation and
    held-out suppression, controls, and restoration.
\end{enumerate}

\section{Related Work}
\label{sec:related}

\subsection{Read-write views of Transformer computation}

The Transformer applies attention and position-wise feed-forward networks to a
residual stream \cite{vaswani2017attention}. Geva et al. interpret Transformer
feed-forward layers as key-value memories: first-layer weights detect input
patterns and second-layer weights contribute output directions
\cite{geva2021transformer}. This provides the closest conceptual precursor to
our read/write factorization. \DAWN{} changes the architectural status of that
factorization. Its read and write directions directly define an executable
rank-1 state transition, and its address is constructed from those same
functional parameters.

Memory layers make parameter access explicit. Product Key Memory uses
factorized keys for efficient exact retrieval from large learned memories
\cite{lample2019large}; later work scales trainable key-value lookup to much
larger parameter counts \cite{berges2024memory}. These systems retrieve stored
values. \DAWN{} instead addresses operators that first read from the current
state and then write a state-dependent scalar back into the representation.

\subsection{Sparse addressing and fine-grained conditional computation}

Sparsely-gated mixtures of experts conditionally activate a small subset of
large expert networks \cite{shazeer2017outrageously}, and Switch Transformers
show that simple routing can scale this pattern \cite{fedus2022switch}. PEER
(parameter efficient expert retrieval) moves to much finer granularity by
using product-key retrieval over more than a million small experts
\cite{he2024mixture}. PEER is the closest prior work at the level of atomic
conditional computation: it retrieves singleton feed-forward experts.
\DAWN{} addresses explicit RW state-transition operators, derives each address
from the operator's read/write function, applies the mechanism to Q, K, V, and
RST, and reuses route-specific pools across depth. Conversely, the current
\DAWN{} implementation does not provide PEER-style indexed sparse execution;
it performs a dense address scan and dense, chunked RW application.

\subsection{Shared computation and operation reuse across depth}

Universal Transformers reuse a recurrent transformation across depth
\cite{dehghani2019universal}; ALBERT reduces parameters through cross-layer
sharing \cite{lan2020albert}. Sparse Universal Transformers combine depth
sharing with sparse experts \cite{tan2023sparse}, and MoEUT adapts mixtures of
experts to shared-layer language models \cite{csordas2024moeut}. MoEUT is a
close architectural comparison for global reuse, but its reusable objects are
expert modules inside a shared Transformer layer. \DAWN{} reuses explicit
route-specific RW pools and addressing projections while retaining
layer-specific LayerNorm parameters and attention output projections. It
therefore does not repeat one completely shared block.

Dynamic parameterization offers another route to input-dependent functions.
HyperNetworks generate weights for another network
\cite{ha2017hypernetworks}, while CondConv forms example-conditioned
convolutional kernels from learned experts \cite{yang2019condconv}. \DAWN{}
does not synthesize a dense weight matrix. It exposes a composition of fixed,
identifiable rank-1 RW operators and ties their addresses to their execution
directions.

\subsection{Mechanistic analysis and causal intervention}

Mechanistic interpretability studies model behavior through identifiable
components and causal interventions. Work on IOI isolates an attention-head
circuit and evaluates faithfulness, completeness, and minimality
\cite{wang2023interpretability}. Activation patching and scalable
approximations localize behavior to components
\cite{kramar2024atp}. RAVEL emphasizes that neuron-level representations may
be entangled and evaluates methods against causal criteria
\cite{huang2024ravel}. Our analysis treats a layer, route, and operator
identity as a site, freezes localization before confirmatory evaluation, and
uses direct numerator suppression, matched random circuits, and exact
same-example restoration. The explicit unit helps specify interventions, but
does not guarantee a human-readable interpretation.

\section{DAWN-SRW}
\label{sec:method}

\subsection{Overview}

Let a token's residual state be \(x\in\mathcal{X}=\R^D\). For each route
\(a\in\{Q,K,V,\mathrm{RST}\}\), the model maps \(x\) to an operation query
\(q_a(x)\in\mathcal{Z}_a\). An operation space is a learned coordinate space
whose points identify executable state-transition operators rather than
represented states. Operator \(i\) has address \(k_{a,i}\in\mathcal{Z}_a\),
and the geometry between \(q_a(x)\) and \(k_{a,i}\) determines whether its
read-write function executes.

The conceptual transition for route \(a\) is
\begin{equation}
T_a(x)=x+\sum_i
G_a\!\left(q_a(x),K_a(r_{a,i},w_{a,i})\right)
\langle x,r_{a,i}\rangle w_{a,i}.
\label{eq:core_transition}
\end{equation}
Here \(K_a\) builds a functional address from read and write directions, and
\(G_a\) performs state-conditioned addressing. Sections
\ref{sec:operation-space}--\ref{sec:implemented-boundary} give the implemented
normalization, composition denominator, and route scale omitted from this
summary.

\subsection{Learned Operation Spaces}
\label{sec:operation-space}

Representation space and operation space serve different roles:
\[
\begin{array}{l}
\text{representation space: what is currently represented},\\
\text{operation space: which transformation should execute}.
\end{array}
\]
The evaluated model uses route width \(R=256\). One shared pair of learned
probes \(P_r,P_w\in\R^{D\times R}\) maps the functional read/write directions
of every route to address features. With
\(\operatorname{unit}(z)=z/\max(\norm{z}_2,\epsilon)\), the implemented
operator address is
\begin{align}
\bar r_{a,i}&=\operatorname{unit}(r_{a,i}),&
\bar w_{a,i}&=\operatorname{unit}(w_{a,i}),\nonumber\\
u_{a,i}&=\operatorname{unit}(\bar r_{a,i}^{\top}P_r),&
v_{a,i}&=\operatorname{unit}(\bar w_{a,i}^{\top}P_w),\nonumber\\
k_{a,i}&=\operatorname{unit}(u_{a,i}\od v_{a,i}).
\label{eq:rw_address}
\end{align}
This generalized coordinate-wise bilinear construction makes address identity
a learned function of what the operator reads and where it writes. It is not
an arbitrary expert ID. The shared probes align QK, V, and RST addresses to
the same route-width coordinate convention, but the operator rows themselves
belong to separate route-specific pools.

\subsection{Explicit Read-Write Operators}
\label{sec:rw}

Each operator has a normalized read direction \(\bar r_{a,i}\) and write
direction \(\bar w_{a,i}\). Its executable function is
\begin{equation}
\op_{a,i}(x)=\langle x,\bar r_{a,i}\rangle\bar w_{a,i}
=\bar w_{a,i}\bar r_{a,i}^{\top}x.
\label{eq:rw_operator}
\end{equation}
This is an explicit rank-1 state transition. The read direction specifies what
scalar is extracted from the current state; the write direction specifies
where that scalar contributes. Unlike a retrieved static value, the output
depends on the current residual state even after the operator is selected.

\subsection{State-Conditioned Operator Addressing}
\label{sec:addressing}

The normalized operation query is a direct projection of the route input:
\begin{equation}
q_a(x)=\operatorname{unit}(xP_a+b_a).
\label{eq:query}
\end{equation}
A separate direct projection produces a token-dependent boundary:
\begin{align}
\tau_a(x)&=-1+2\sigma(xu_a+c_a),\\
\rho_{a,i}(x)&=q_a(x)^\top k_{a,i},\\
m_{a,i}(x)&=\rho_{a,i}(x)-\tau_a(x).
\label{eq:directtau}
\end{align}
The evaluated \texttt{linear\_angular} rule uses
\begin{equation}
g_{a,i}(x)=
\operatorname{clip}\!\left(
\frac{m_{a,i}(x)}
{\max(1-\tau_a(x),10^{-4})},0,1\right).
\label{eq:angular_gate}
\end{equation}
Thus exact functional support is the set
\(\{i:m_{a,i}(x)>0\}\). Evaluation pruning is disabled, so the admission and
execution weights are both \(g_{a,i}\).

Composition normalizes by admitted mass:
\begin{align}
d_a(x)&=\left[\max\!\left(\sum_i g_{a,i}(x),1\right)\right]^{p_a},\\
\Delta_a(x)&=
\frac{\sqrt{D/L}}{d_a(x)}
\sum_i g_{a,i}(x)
\langle x,\bar r_{a,i}\rangle\bar w_{a,i}.
\label{eq:implemented_composition}
\end{align}
The denominator powers are \(p_Q=p_K=0.5\), \(p_V=1.0\), and
\(p_{\mathrm{RST}}=1.2\). The fixed output scale is
\(\sqrt{D/L}\), with no learned pool-strength parameter.

\subsection{Attention and Residual-State Transitions}
\label{sec:block}

At layer \(\ell\), a layer-specific normalization produces
\(\tilde x_\ell=\operatorname{LN}^{(1)}_\ell(x_\ell)\).
Separate Q, K, and V operation queries and DirectTau boundaries are computed
from \(\tilde x_\ell\). Q and K address the same 4,600-row QK pool in two
separate passes; V addresses a separate 14,500-row pool. Their RW compositions
form full-\(D\) Q, K, and V states, which are reshaped into heads and passed
through standard causal scaled dot-product attention:
\begin{align}
A_\ell&=\operatorname{softmax}\!\left(
\frac{Q_\ell K_\ell^\top}{\sqrt{d_h}}+M_{\mathrm{causal}}\right)V_\ell,\\
y_\ell&=x_\ell+A_\ell W^{O}_{\ell}.
\label{eq:attention}
\end{align}
After attention, a second layer-specific normalization
\(\tilde y_\ell=\operatorname{LN}^{(2)}_\ell(y_\ell)\) is newly addressed by
the RST route. The resulting composition uses its own 29,300-row pool:
\begin{equation}
x_{\ell+1}=y_\ell+\Delta_{\mathrm{RST}}(\tilde y_\ell).
\label{eq:rst}
\end{equation}
RST therefore depends on the contextualized post-attention state, not the
pre-attention route query.

\subsection{Global Reuse Across Depth}
\label{sec:reuse}

The QK, V, and RST read/write pools; the two RW-to-address probes; the Q/K/V
query projection; the RST query projection; and their DirectTau projections
are shared across all \(L\) layers. Q and K share read/write rows but retain
separate query slices, tau values, gates, and outputs. The layer-specific
parameters are two LayerNorms and the attention output projection
\(W^O_\ell\). Positional and token embeddings and the final normalization are
model-level parameters. Consequently, \DAWN{} provides cross-depth operation
reuse without claiming complete block sharing.

\subsection{Implemented Execution and Compute Boundary}
\label{sec:implemented-boundary}

The implementation shards operator rows across the model mesh and processes
them in dense chunks. The 400M configuration uses one QK chunk, one V chunk,
and four RST chunks. Every query scores the full local address pool; every
operator row participates in dense read and write contractions before
cross-shard reduction. Exact zeros in Equation~\ref{eq:angular_gate} therefore
describe \emph{functional} support, not an indexed sparse kernel.

The evaluated architecture also keeps RW execution in the full residual
dimension \(D\). The operation space is low-dimensional only as an address
space. A hypothetical executor can omit exactly zero RW terms without changing
the mathematical output, but this conditional execution opportunity is not
implemented or timed here.

\subsection{Matched 400M dense control}

The dense control has 393,896,960 measured parameters, width 1,280, feed-forward
width 5,120, 18 layers, and 20 heads. It uses the same tokenizer, vocabulary,
sequence length, training-token count, seed, batch size, mesh, learning rate,
warmup ratio, weight decay, and zero dropout as the primary model. The
parameter difference is 96,252, or 0.0244\% of the dense model. This comparison
tests performance retention under matched scale and training exposure; it is
not a formal equivalence test.

\subsection{Evaluation protocols}

The C4 protocol evaluates 610 complete global batches from the fixed
10M-token capped packed-validation view: 19,520 sequences and 9,974,720 valid
next-token targets. Cross-entropy, perplexity, and next-token accuracy use
float32 scoring. The zero-shot protocol uses \texttt{lm-eval} 0.4.2 with no
few-shot examples and no task limit on LAMBADA, HellaSwag, PIQA, ARC-Easy,
ARC-Challenge, and WinoGrande. The primary metric is raw accuracy for LAMBADA
and WinoGrande and normalized accuracy for the other four tasks. The mean is
an unweighted mean of these six metrics.

\subsection{Mechanistic localization and frozen intervention protocol}
\label{sec:protocol}

We define a site by layer, route, token position, and global operator identity.
IOI discovery uses 119 independent paired-correct units. Sites are ranked by
absolute discovery mean contribution importance. We choose the smallest
audited prefix that reaches at least 0.70 cumulative absolute importance and
0.95 split top-\(k\) overlap. The resulting 4,096-site identity, route/layer
composition, score, and intervention specification are frozen before
validation.

The primary causal score is the summed-log-probability margin between the
correct indirect object and the source name. Circuit-wide suppression zeros
only the selected operators' execution numerator at target positions while
retaining the full production denominator. Four control families each contain
100 frozen-size circuits that exclude circuit sites: equal-count random,
same-layer random, activation-matched, and route-frequency-matched. Exact
restoration reinserts the same-example selected numerator after suppression,
again under the production denominator. Validation uses 123 independent
paired-correct units; the held-out test accessor is opened only after the
validation result and unchanged specification are finalized. We report 95\%
bootstrap confidence intervals and two-sided paired permutation tests where
specified.

\subsection{Descriptive larger-scale evaluation at 1.3B}

The 1.272B checkpoint reaches 2.835879 C4 cross-entropy, 17.045382
perplexity, 0.437099 token accuracy, and a 0.485844 six-task mean. It was
trained for 19.999B tokens, about half the 400M training-token count, and no
completed matched dense 1.3B result is admitted to this study. These results
therefore describe a larger trained \DAWN{} model; they are neither a
controlled scaling curve nor a dense-model comparison.

\section{Discussion}
\label{sec:discussion}

\subsection{What the results establish}

The evaluated model shows that a language model can construct attention and
post-attention residual updates by state-conditionally addressing explicit
RW operators. The matched 400M comparison shows performance retention under
the measured protocols. The support profile shows that the gate has exact
input-conditioned zeros, and the IOI study shows that operator sites can form
a discovery-frozen circuit whose suppression and restoration causally control
behavior on held-out data.

These claims are deliberately narrower than a theory of language reasoning as
discrete programs. The causal result is strong for the specified IOI task and
intervention, not universal across tasks or scales. RAVEL, ARC, and 1.3B IOI
demonstrate that explicit units do not make successful localization automatic.

\subsection{Operation spaces as a computational abstraction}

An operation space separates represented state from executable operation
identity. A query describes what transformation is currently relevant; an
address identifies a reusable transformation; and an RW operator specifies
the executed function. Because the address is derived from read/write
parameters, selection geometry and execution function are coupled rather than
assigned independent labels.

This coupling is an architectural constraint, not proof of semantic
interpretability. An operator may be explicit, observable, and causally
testable while participating in distributed or polysemantic computation.
The IOI circuit's 4,096 sites across all layers is consistent with this
distributed view.

\subsection{Toward Low-Dimensional Operation-Space Execution}
\label{sec:future-low-d}

The evaluated model uses low-dimensional addresses but full-\(D\) RW
execution. A separate repository implementation is an \emph{implemented but
not yet fully evaluated low-dimensional extension}. It associates each
operation-space address with \(D\!\leftrightarrow\!R\) interfaces, selects
spaces independently for Q, K, V, and RST, and performs local RW composition
before writing back:
\begin{align}
h_m&=P_m^\top x,\\
z_{a,m}&=\sum_i g_{a,m,i}(h_m)
\langle h_m,r_{a,m,i}\rangle w_{a,m,i},\\
\Delta x_a&=\sum_m\alpha_{a,m}(x)B_m z_{a,m}.
\label{eq:lowd_preview}
\end{align}
Its local operator remains globally rank-1 because
\(B_m w_i r_i^\top P_m^\top=(B_mw_i)(P_mr_i)^\top\). Compilation,
symbolic parameter counts, reduced JIT forward/backward, and gradient
contracts have been checked, and limited early-training observations exist.
There is no completed controlled language-model evaluation or realized
efficiency measurement. The current reference path executes all spaces
densely; candidate-restricted dispatch and an accelerator-native kernel remain
future work. Appendix~\ref{app:lowd} records the boundary in more detail.

\subsection{Limitations}

The current implementation evaluates full address and operator pools densely.
Exact functional support does not imply current sparse execution, and even the
exact-support accounting remains 2.1168 times the matched dense Transformer's
backbone accounting. No production latency, energy, or hardware advantage is
measured.

The central causal evidence is confined to IOI and does not automatically
generalize to every task. RAVEL, ARC, and the selected 1.3B IOI replication
provide valid negative boundaries. The 400M and 1.3B checkpoints have
different parameter and training-token budgets, so they do not define a
controlled scaling curve. Operator-level causal units need not map one-to-one
to human-readable concepts. The low-dimensional extension has not received a
controlled evaluation. Finally, the present work does not establish language
reasoning as universally discrete operator programs.

\section{Conclusion}

\DAWN{} formulates language-model computation as state-conditioned addressing
in learned operation spaces populated by explicit RW state-transition
operators. The architecture separates represented state from operation
identity, derives addresses from read/write function, and reuses route-specific
operator pools to construct Q, K, V, and post-attention residual transitions
across depth. It retains measured language-model performance relative to a
matched 400M dense control. A discovery-frozen Q/K-centered operator circuit is
causally necessary under suppression and recoverable under exact restoration
on independent validation and fully held-out IOI inputs. The model also shows
exact input-conditioned functional support. These findings support addressed
RW operators as a viable and causally analyzable computational substrate, but
do not establish benchmark superiority, universal operator programs, or
current hardware efficiency.

\section{Exact Addressing and Composition Equations}
\label{app:equations}

This appendix restates the production computation as a compact reference. Raw
read and write parameters are normalized in float32 before being cast for
dense contractions:
\[
\bar r_i=\frac{r_i}{\max(\norm{r_i}_2,\epsilon)},\qquad
\bar w_i=\frac{w_i}{\max(\norm{w_i}_2,\epsilon)}.
\]
One pair of model-level probes is shared across QK, V, and RST:
\[
\begin{aligned}
u_i&=\operatorname{unit}(\bar r_i^\top P_r),&
v_i&=\operatorname{unit}(\bar w_i^\top P_w),\\
k_i&=\operatorname{unit}(u_i\od v_i).&&
\end{aligned}
\]
The query and threshold use separate direct projections:
\[
\begin{aligned}
\hat q_a&=\operatorname{unit}(xP_a+b_a),\\
\tau_a&=-1+2\sigma(xu_a+c_a),&
\rho_i&=\hat q_a^\top k_i.
\end{aligned}
\]
For \texttt{linear\_angular} composition:
\[
g_i=e_i=
\operatorname{clip}\!\left(
\frac{\rho_i-\tau_a}{\max(1-\tau_a,10^{-4})},0,1\right)
\]
because evaluation pruning is disabled. Padding rows are masked to zero.
Let \(M_a=\sum_i g_i\). The production route result before causal attention or
residual addition is
\[
\Delta_a(x)=
\sqrt{\frac{D}{L}}\,
\frac{\sum_i e_i\langle x,\bar r_i\rangle\bar w_i}
{\max(M_a,1)^{p_a}},
\]
with \(p_Q=p_K=0.5\), \(p_V=1.0\), and \(p_{\mathrm{RST}}=1.2\).
Operator rows are sharded over the model axis; local numerators and admission
mass are reduced across shards. Chunking changes the contraction schedule, not
the equation.

\subsection{Suppression, controls, and restoration}

For a correct candidate \(c\) and source candidate \(s\), the primary score is
\[
\mathcal{M}=\sum_{t\in c}\log p(t)-\sum_{t\in s}\log p(t).
\]
Suppression zeros the frozen sites' execution numerator at specified token
positions. It leaves admission mass and the production denominator unchanged.
Controls use the same 4,096-site count and exclude all circuit sites.
Activation matching conditions on layer, route, and the discovery mean
pre-scale operator-output-norm quantile. Restoration executes a distinct
intervention: after suppression, it adds back the exact selected same-example
numerator under the unchanged denominator.

\section{Low-Dimensional Operation-Space Extension}
\label{app:lowd}

The low-dimensional extension uses one shared atlas of \(M=8\) operation-space
addresses, shared \(D\!\to\!R\) read interfaces \(P_m\), and shared
\(R\!\to\!D\) write interfaces \(B_m\). Q, K, V, and RST have independent
query projections and select two atlas entries independently. Route-specific
tau maps and operator banks remain separate. For local operator \(i\) in space
\(m\),
\[
\begin{aligned}
\op^{\mathrm{global}}_{a,m,i}(x)
&=B_m w_{a,m,i}r_{a,m,i}^{\top}P_m^\top x\\
&=(B_mw_{a,m,i})(P_mr_{a,m,i})^\top x,
\end{aligned}
\]
so the induced global transformation remains rank-1.

The 40M reference has 40,341,088 parameters, \(D=432\), \(R=128\), 12
layers, six heads, and top-2 space selection. Repository-local compilation,
abstract-tree and symbolic parameter counting, shared-key and independent
route selection, legacy-checkpoint rejection, reduced JIT
forward/backward, selector metrics, and gradient contracts have passed.
Some early-training observations are recorded, but the exact deployment and
complete controlled language-model evaluation are absent. No latency,
throughput, energy, or hardware-efficiency result exists. The reference path
executes every space densely; future work requires candidate-restricted
dispatch and an accelerator-native execution kernel.
